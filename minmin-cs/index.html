01 · Latar belakang

Terlalu banyak request, VM terbatas

Task scheduling

Memilih urutan task lalu memetakannya ke sumber daya yang sesuai. Targetnya waktu eksekusi lebih pendek dan sumber daya terpakai optimal.

Load balancing

Memindahkan beban dari resource yang berat ke yang ringan agar sistem stabil dan tidak overload.

NP-complete

Keduanya termasuk masalah NP-complete, sehingga dipakai heuristik dan metaheuristik, bukan mencoba semua kombinasi.

Workflow ilmiah berbentuk DAG: task punya ketergantungan, jadi urutan eksekusi harus menghormati precedence constraints (PC).

02 · Ide utama paper

Dua tahap, satu jadwal

1 · Modified Min-Min

Menghasilkan populasi awal berupa task order yang sudah memenuhi PC.

2 · Cuckoo Search

Membangkitkan task order baru ("telur"), bermigrasi ke arah order terbaik, dan membuang order terburuk.

5 workflow ilmiah, 4 pembanding, 5 parameter QoS, plus uji statistik ANOVA.

Celah yang diklaim: studi sebelumnya banyak berfokus pada makespan saja. EMMCA menargetkan makespan dan load balancing sekaligus.

03 · Model masalah

Workflow DAG di beberapa server

Workflow

$$R^{flow}=\{R_i,\;CO_{link},\;CO_{time}\}$$

Task entry tanpa predecessor, task exit tanpa successor. Setiap link antar task membawa waktu komunikasi.

Platform

Server \(N=\{N_1,\dots,N_k\}\), tiap server memiliki sejumlah VM \(Q=\{Q_1,\dots,Q_p\}\). Scheduler memetakan task dari task queue ke VM.

$$CO_{time}(R_i,R_j)=\begin{cases}0 & \text{satu server}\\ CO_{link} & \text{lainnya}\end{cases}$$

Satu server = tanpa biaya komunikasi. Itu sebabnya penempatan task yang saling bergantung penting.

04 · Waktu eksekusi

ECT, EFT, dan makespan

Estimated computation time

Matriks durasi task \(R_i\) pada VM \(Q_j\).

$$\tau^{ECT}_{ij}\;(m\times n)$$

Minimum execution time

$$\tau^{MET}=\min\{\tau^{ECT}(R_i,Q_n)\}$$

Earliest start & finish

EST bernilai 0 untuk task entry. Untuk task lain, EST ditentukan oleh selesainya predecessor ditambah waktu transfer data (rumus lengkap di paper memuat suku MET; di sini disederhanakan).

$$\tau^{EFT}(R_i,Q_j)=\tau^{ECT}_{ij}+\tau^{EST}(R_i,Q_j)$$

Makespan

$$m_{SPAN}=\min\{\tau^{EFT}(R_{exit},Q)\}$$
05 / 20

05 · Parameter QoS

Load balance, speedup, efficiency, cost

Load balance

$$L_{balance}=\frac{L^{N}_{avg}}{m_{SPAN}},\quad L^{N}_{avg}=\frac{\sum\tau^{pr}}{p}$$

Rasio rata-rata beban mesin terhadap makespan.

Speedup & efficiency

$$SP^{up}=\frac{\min\left[\sum\tau^{ECT}_{ij}\right]}{m_{SPAN}},\quad Eff=\frac{SP^{up}}{p}\times100$$

Seberapa cepat dibanding eksekusi berurutan, dan seberapa efisien VM dipakai.

Cost

$$C_{cost}=\sum\tau^{pr}_{ij}\times Cost(Q_j)$$

Waktu proses dikalikan tarif per unit waktu tiap VM.

Fungsi tujuan

Dua tujuan utama: makespan minimum dan beban VM yang merata. Speedup, efficiency, dan cost menjadi parameter pendukung.

06 · Basis: Modified Min-Min

Task tercepat dulu, tetap patuh PC

Min-Min klasik (penjelasan umum, bukan dari paper)

  1. Untuk tiap task yang belum dijadwalkan, cari VM dengan waktu selesai terkecil.
  2. Pilih task yang waktu terkecilnya paling kecil.
  3. Tetapkan ke VM tersebut, perbarui ketersediaan VM, ulangi.

Versi modifikasi di EMMCA

Tugasnya dependen, sehingga prioritas dihitung dari τECT minimum dengan syarat PC terpenuhi.

$$P(R_i)=\min\{\min\{\tau^{ECT}(R_i,Q_{1..p})\}\}\ \text{dengan PC}$$

Ukuran populasi = jumlah task order awal. Setiap order dibuat dari matriks τECT yang berbeda pada struktur workflow yang sama.

07 · Teori Cuckoo Search

Burung kukuk menitip telur

Tiga aturan ideal (Yang & Deb, 2009)

  1. Setiap kukuk meletakkan satu telur di sarang acak.
  2. Telur (solusi) berkualitas dari sarang terbaik diwariskan.
  3. Jumlah sarang tetap; induk menemukan telur asing dengan peluang \(P_a\), lalu membuangnya atau membuat sarang baru.

Lévy flight

$$x_i^{t+1}=x_i^t+\alpha\oplus \text{Lévy}(\lambda)$$

Langkah acak berekor tebal: sebagian besar langkah kecil (eksploitasi), kadang melompat jauh (eksplorasi).

Lévy flight adalah dasar teori. Pada EMMCA, "telur" berupa task order, sehingga dipakai operator diskret (slide berikut).

08 / 20

08 · Laying: membuat task order baru

Y offspring per parent

Jumlah offspring

$$Y=(NOr_{max}-NOr_{min})\times Rand[0,1]+NOr_{min}$$

Setiap parent order menghasilkan Y order baru, dengan Y antara \(NOr_{min}\) dan \(NOr_{max}\).

Modification radius

$$MoR_t=\left[\lambda\times\frac{\text{current schedule's }K}{\text{total schedule }K}\right]\times(V_{hi,t}-V_{low,t})$$

MoR membatasi berapa task yang boleh bergeser posisi di dalam legal sequence.

Legal sequence

Kumpulan task yang masih memenuhi PC jika ditukar posisinya.

Dikecualikan

Task entry dan exit tidak ikut diubah karena melanggar PC.

Seleksi

Offspring terbaik menjadi prime order sebagai pembanding berikutnya.

09 / 20

09 · Immigration & terminasi

Bergerak ke arah order terbaik

Cuckoo immigration

Task yang sama dipindahkan antar order mengikuti legal sequence milik prime order, dengan probabilitas ρ, tanpa melanggar dependensi. Order hasil migrasi menggantikan yang lama jika fitness lebih baik.

Syarat migrasi

Hanya order dengan comparable legal sequence (indeks awal sama dengan prime order). Jika jumlah legal sequence-nya sama dengan prime order, order tersebut tidak dimigrasikan, supaya tidak terjebak di optimum lokal.

Order terburuk dibuang

Menjaga ukuran populasi tetap dan keseimbangan "populasi burung".

Terminasi

Berhenti setelah jumlah iterasi tertentu.

10 · Kerangka enam fase

Dari program aplikasi ke metrik QoS

I · Application program

Pernyataan \(R_1,\dots,R_p\) dari request pengguna.

II · Dekomposisi

Program dipecah menjadi workflow DAG.

III · Computing priority

Modified Min-Min + Cuckoo Search menghasilkan task order terbaik.

IV · Task order queue

Order terbaik masuk antrean untuk scheduler.

V · Task mapping

Pemetaan ke VM memakai τECT dan τEFT, dengan duplikasi task entry di beberapa server.

VI · Prime objectives

Hitung makespan, load balance, speedup, efficiency, dan cost.

Urutan eksekusi EMMCA

12 · Pseudocode

Laying lalu immigration, berulang

INISIALISASI populasi task order
  (Modified Min-Min)
HITUNG fitness tiap order
TETAPKAN prime order & prime value
SELAMA belum konvergen:
  UNTUK tiap order dalam populasi:
    buat legal sequence
    tentukan Y, hitung MoR
  evaluasi fitness semua offspring
  jika current < prime: perbarui prime
  perbarui New_Population (POPsize)
  UNTUK tiap legal sequence prime order:
    immigration dengan probabilitas ρ
  evaluasi ulang fitness
  jika current < prime: perbarui prime
  perbarui populasi
  jika iterasi >= MAXGEN: konvergen
  iterasi = iterasi + 1
HITUNG makespan & load balance
  dari best order

18 · Evaluasi kritis

Kuat di makespan, ada trade-off

Kelebihan

Makespan EMMCA paling rendah pada seluruh 15 konfigurasi di tabel paper. Penurunan terbesar terlihat pada Cybershake dan LIGO Inspiral.

Keterbatasan (paper)

Cenderung ke optimum lokal, sensitif terhadap discovery rate dan ukuran populasi, makin mahal saat beban naik, dan mengasumsikan resource statis tanpa deadline, biaya, atau energi.

Cost tidak selalu terendah

Contoh SIPHT 60 task: HEFT 1.598.452 vs EMMCA 2.809.108. Pada LIGO 30 task, Min-Min juga lebih murah.

Catatan pembacaan

Arah "load balancing berkurang" tidak seragam: pada Montage vs CPOP, nilai EMMCA justru sekitar 1% lebih tinggi, sedangkan teks LIGO menyebut hasilnya kurang memuaskan padahal nilai tabelnya tinggi. Perlu hati-hati mengutipnya.

Cakupan

Pembanding hanya heuristik (Min-Min, HEFT, PETS, CPOP), dan pengujian berupa simulasi Python, belum di cloud nyata.

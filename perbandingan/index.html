02 · Arsitektur Komputasi

Hierarki 3-Tier (IFC) vs. Multi-Server Cloud

IPSO-GWO · IoT-Fog-Cloud (IFC)

Kolaborasi Tiga Tingkat

1. IoT / Edge Layer (5 perangkat): Berada paling dekat pengguna. Menjalankan task ringan & sensitif delay secara lokal tanpa biaya transmisi (biaya transfer = $0).

2. Fog Layer (5 node): Perangkat perantara (1200–1600 MIPS). Mengurangi beban cloud dengan latensi moderat dan konsumsi daya seimbang.

3. Cloud Layer (5 node): Server data center besar (1600–2000 MIPS). Kapasitas tak terbatas untuk komputasi berat, tetapi dikenakan biaya finansial dan latensi transmisi jaringan.

EMMCA · Clustered Cloud Servers

Topologi Server & VM Terpusat

1. Struktur Server: Kumpulan server fisik \(N = \{N_1, N_2, \dots, N_k\}\) di pusat data cloud yang terhubung melalui communication link (\(CO_{\text{link}}\)).

2. Virtual Machine: Setiap server memiliki sejumlah mesin virtual \(Q = \{Q_1, Q_2, \dots, Q_p\}\) dengan kapasitas pemrosesan yang bervariasi.

3. Sifat Komunikasi: Waktu komunikasi adalah 0 jika dua task dependen dieksekusi pada server fisik yang sama, dan bernilai positif jika melintasi batas server.

Implikasi Desain: IPSO-GWO memperhitungkan latensi jaringan uplink/downlink bertingkat nyata, sedangkan EMMCA mengoptimalkan penempatan task di dalam cluster datacenter.

03 / 17

03 · Filosofi Hybrid

Bagaimana Kedua Algoritma Menggabungkan Kekuatan?

IPSO-GWO: Metaheuristik + Metaheuristik

Transisi Sekuensial di Titik Tengah

Fase 1 (Iterasi 1–50) · IPSO: Memulai dengan populasi partikel acak. Bobot inersia menurun secara linear (\(w: 0.8 \to 0.3\)). Partikel melakukan penjelajahan luas (eksplorasi) lalu berangsur menyempit (eksploitasi).

Fase 2 (Iterasi 51–100) · GWO: Solusi terbaik global (\(gbest\)) dari IPSO dijadikan Serigala Alpha (\(\alpha\)) awal. Kawanan serigala (\(\beta, \delta, \omega\)) mengepung target untuk mencegah jebakan lokal optimum PSO dan menyempurnakan solusi akhir.

EMMCA: Heuristik + Metaheuristik

Pondasi Cerdas yang Dievolusikan

Tahap 1 · Modified Min-Min (Heuristik): Membangun populasi awal berdasarkan perhitungan \(\tau^{\text{ECT}}\) dan kendala presedensi (PC). Solusi awal sudah berkualitas tinggi (disebut Prime Order), bukan acak murni!

Tahap 2 · Cuckoo Search (Metaheuristik): Mereorganisasi urutan tugas melalui Egg-Laying Radius (MoRt) dan operator imigrasi legal. Mekanisme brood parasitism dan Lévy flight mencari ruang solusi baru secara cerdas tanpa melanggar dependensi graf.

Perbedaan Utama: IPSO-GWO murni mengandalkan pencarian stokastik bertingkat, sedangkan EMMCA memberikan "kepala start" berkualitas tinggi dengan heuristik Min-Min deterministik.

04 · Representasi Solusi

Pemetaan Langsung vs. Antrean Permutasi Prioritas

IPSO-GWO · Direct Discrete Mapping

Vektor Alokasi Task ke VM

$$P = (v_1, v_2, \dots, v_M), \quad v_i \in [1, \text{VMs}]$$
  • Panjang array sama persis dengan jumlah task (\(M\)). Nilai pada indeks \(i\) adalah ID mesin virtual yang mengeksekusi task \(T_i\).
  • Struktur vektor tidak berubah saat transisi dari partikel IPSO menjadi serigala GWO.
  • Penanganan DAG: Diserahkan ke mesin simulator (FogWorkflowSim) yang menahan eksekusi anak sampai data dari induk selesai ditransfer.
EMMCA · Permutation Priority Queue

Urutan Urut Eksekusi (Legal Sequence)

$$\text{Order} = (R_1, R_4, R_5, R_2, R_3, R_7, R_6, R_8)$$
  • Vektor merepresentasikan urutan prioritas eksekusi task yang wajib mematuhi Precedence Constraints (PC).
  • Task lalu dialokasikan ke VM menggunakan aturan Earliest Completion Time (\(\tau^{\text{EFT}}\)).
  • Fitur Khusus: Menggunakan Task Duplication pada entry task untuk menghilangkan latensi transfer data antar-server.

Trade-off: Vektor IPSO-GWO lebih sederhana tetapi bisa menghasilkan jadwal tidak valid jika dependensi tidak dimonitor ketat; EMMCA menjamin kepatuhan dependensi lewat operator legal sequence.

05 · Fungsi Objektif

Weighted Sum Tiga Metrik vs. Multi-QoS Terpisah

IPSO-GWO · Weighted Sum Formula

Fungsi Objektif Agregat Tunggal

$$F(p) = w_1 \cdot \text{MS} + w_2 \cdot \text{TE} + w_3 \cdot \text{TC}$$

Bobot seimbang: \(w_1 = w_2 = w_3 = 0.2\) (menyisakan fleksibilitas untuk parameter QoS lain).

Makespan (MS): \(\max(FT) - \min(ST)\).

Total Energi (TE): \(E_{\text{active}} + E_{\text{idle}}\), memodelkan konsumsi daya saat sibuk (\(\alpha f V^2\)) dan daya saat idle/sleep mode pada fog & cloud.

Total Biaya (TC): Biaya sewa komputasi ED/FD/CD ditambah biaya transfer data antar node.

EMMCA · Dual Prime Objectives

Makespan & Keseimbangan Beban

$$m_{\text{SPAN}} = \min\{\tau^{\text{EFT}}(R_{\text{exit}}, Q)\}, \quad L_{\text{balance}} = \frac{L_{\text{avg}}^N}{m_{\text{SPAN}}}$$

Tidak digabung ke dalam satu fungsi bobot, melainkan dievaluasi sebagai multi-QoS independen:

Speedup (\(SP^{\text{up}}\)): Rasio total komputasi terhadap makespan.

Efisiensi (\(Eff\)): \(SP^{\text{up}} / p \times 100\%\) terhadap jumlah VM.

Biaya Finansial (\(C_{\text{cost}}\)): Akumulasi waktu eksekusi dikali tarif sewa per VM.

Catatan Kritis: Sama sekali tidak memodelkan konsumsi energi!

IPSO-GWO sangat peduli terhadap dampak lingkungan (Green Computing), sedangkan EMMCA fokus pada efisiensi pemanfaatan kapasitas server (Throughput & Fairness).

09 · Evaluasi Metrik: Biaya Finansial

Total Cost & Dilema Trade-Off Nyata

IPSO-GWO · Rata-rata -12.52%

Anomali Biaya pada Beban Ekstrem

IPSO-GWO sukses memangkas biaya rata-rata 12.52%. Namun pada LIGO dan SIPHT skala 500–1000 task, biaya IPSO-GWO justru lebih mahal 9%–15% dibanding algoritma GSA (didukung uji ANOVA signifikan, \(p < 0.001\)).

Mengapa demikian? Terjadi trade-off alami: demi mengejar makespan cepat dan energi rendah, IPSO-GWO terpaksa menyewa server cloud berbiaya premium.

EMMCA · Biaya Terdistribusi

Degradasi Biaya pada Skala 100 Task

Pada skala kecil (24–50 task), EMMCA menekan biaya sewa VM hingga 7%–13% dibanding HEFT dan PETS.

Namun saat task bertambah ke 100 (khususnya pada Epigenomics, LIGO, dan SIPHT), penulis paper secara jujur mengakui bahwa performa biaya “not up to the mark”. Karena algoritma terus berusaha memangkas makespan, ia memetakan task-task berat ke VM berbiaya satuan tertinggi (Cost/Unit Time tinggi).

Insight Penting: Tidak ada algoritma yang sempurna di semua metrik (No Free Lunch Theorem). Baik IPSO-GWO maupun EMMCA harus membayar "harga moneter" lebih mahal jika menginginkan alur kerja selesai lebih cepat.

10 · Evaluasi Metrik: Keseimbangan Beban

Pemerataan Beban Kerja Mesin Virtual

EMMCA: Load Balancing sebagai Pilar Utama

Mencegah Server Menganggur & Overload

$$L_{\text{balance}} = \frac{L_{\text{avg}}^N}{m_{\text{SPAN}}} = \frac{\sum_{i=1}^K \tau^{\text{pr}} / p}{m_{\text{SPAN}}}$$
  • EMMCA dirancang khusus untuk meminimalkan derajat ketimpangan antar VM.
  • Pengujian ANOVA membuktikan efektivitas pemerataan beban pada Epigenomics (\(F=12.00\)), Montage (\(F=11.87\)), LIGO (\(F=4.67\)), dan SIPHT (\(F=103.32\)) dengan \(p < 0.005\).
  • Pengecualian: Pada CyberShake, nilai \(p = 0.1107\) (tidak berbeda signifikan secara statistik karena pola graf pipih).
IPSO-GWO: Alokasi Berbasis Kapabilitas

Fokus Penyerahan Beban Bertingkat

IPSO-GWO tidak menjadikan rasio load balancing sebagai fungsi fitness.

Konsekuensinya:
• Server fog dan cloud berkecepatan tinggi cenderung menerima lebih banyak tugas kritis.
• Node edge hanya menerima tugas-tugas ringan.
• Distribusi beban antar VM bisa sangat timpang asalkan tujuan makespan, energi total, dan biaya agregat tercapai.

Pemenang di Aspek Load Balancing: EMMCA. Algoritma ini sangat unggul untuk penyedia cloud publik multi-tenant yang ingin menjamin SLA dan utilisasi server yang merata tanpa hotspot.

11 · Kompleksitas & Rekayasa

Kemudahan Implementasi & Beban Komputasi

IPSO-GWO · Kompleksitas Rendah

Struktur Vektor Bersih & Efisien

$$\mathcal{O}(\text{maxIter} \times \text{popSize} \times M \times \text{VMs})$$
  • Kemudahan Kode: Pemetaan task-ke-VM menggunakan array bilangan bulat sederhana. Transisi di iterasi ke-50 bersifat handoff langsung (\(gbest \to \text{wolf}_\alpha\)).
  • Kompleksitas: Bebas dari operasi perbandingan kuadratik partikel (\(\text{popSize}^2\) seperti GSA), sehingga tetap sangat cepat untuk 1.000 task.
EMMCA · Kompleksitas Logika Graf

Validasi Dependensi & Rekayasa Imigrasi

$$\mathcal{O}(\text{Iter} \times \text{Nests} \times M^2 + \text{Graph Check})$$
  • Tantangan Kode: Setiap operasi laying cuckoo (MoRt) dan imigrasi wajib memvalidasi Legal Sequence agar pertukaran urutan tidak membalik dependensi parent-child DAG.
  • Overhead: Membutuhkan waktu CPU algoritma yang lebih intensif saat graf workflow menjadi sangat besar dan memiliki rantai dependensi yang dalam.

Aspek Rekayasa: IPSO-GWO lebih ramah untuk diintegrasikan ke orkestrator kontainer (seperti Kubernetes/FogWorkflowSim), sementara EMMCA memerlukan parser DAG dan penegak presedensi yang ketat.

12 · Evaluasi Kritis

Batasan & Limitasi Menurut Penulis Paper

Limitasi IPSO-GWO (Awad et al., Hal. 25)
  • Sensitivitas Parameter: Sangat bergantung pada penalaan rentang bobot inersia (\(w_{\text{begin}}, w_{\text{end}}\)), koefisien akselerasi \(c_1, c_2\), dan rasio titik perpindahan fase (50:50).
  • Suboptimal Stagnation: Masih ada probabilitas terjebak pada optimum lokal jika populasi kehilangan diversitas sebelum fase serigala mengambil alih.
  • General-Purpose Nature: Algoritma tidak memanfaatkan karakteristik heuristik alur kerja secara langsung (berbeda dengan list scheduling).
  • Penyederhanaan Daya: Model mengasumsikan daya konstan tanpa memperhitungkan Dynamic Voltage & Frequency Scaling (DVFS).
Limitasi EMMCA (Choudhary & Rajak, Hal. 27–28)
  • Pengabaian Energi: Sama sekali tidak memodelkan parameter konsumsi daya atau dampak emisi karbon komputasi.
  • Asumsi Sumber Daya Statis: Mengasumsikan ketersediaan VM dan kapasitas bandwidth konstan tanpa memodelkan jitter jaringan, downtime, atau kegagalan node (fault tolerance).
  • Degradasi Biaya & Load Balance: Pada skala 100 task pada Epigenomics dan SIPHT, load balancing dan total biaya mengalami penurunan performa.
  • Skalabilitas Terbatas: Belum pernah diuji pada alur kerja berskala di atas 100 task.

13 · Contoh Kasus Nyata I

Sistem Peringatan Dini Gempa (CyberShake)

Karakteristik Alur Kerja Seismik

Workflow CyberShake: Menghitung Probabilistic Seismic Hazard Analysis (PSHA) dengan mensimulasikan gelombang seismik sintetis akibat pergeseran lempeng bumi.

Kebutuhan Nyata:
• Tahap awal (ekstraksi getaran seismometer) butuh latensi sangat rendah (< 2 detik) untuk membunyikan sirine darurat.
• Tahap lanjut (simulasi perambatan gelombang tanah 3D) membutuhkan ratusan gigaflop komputasi intensif.

Rekomendasi Algoritma: IPSO-GWO

Alasan Pemilihan:
✓ Arsitektur Edge-Fog-Cloud cocok sempurna: Task deteksi awal dieksekusi di Edge Gateway sesar gempa. Agregasi data regional diproses di Fog stasiun BMKG. Simulasi 3D penuh dialirkan ke Cloud Data Center.
✓ Mengurangi beban bandwidth komunikasi saat bencana.

Batasan & Asumsi: Mengasumsikan tower komunikasi tidak padam pasca gempa utama; jika jaringan seluler putus, task fog tidak dapat di-offload ke cloud.

14 · Contoh Kasus Nyata II

Surveilans Genomik Rumah Sakit (Epigenomics & SIPHT)

Karakteristik Alur Kerja DNA

Workflow: Pemetaan sekuensing Illumina Solexa (Epigenomics) dan anotasi RNA bakteri patogen (SIPHT) untuk diagnosa cepat infeksi pasien kritis di rumah sakit.

Kebutuhan Nyata:
• Alur kerja berbasis batch dengan ribuan potongan reads DNA berukuran besar (ratusan GB data mentah).
• Memerlukan utilisasi memori dan prosesor server yang maksimal agar antrean pasien tidak menumpuk.

Rekomendasi: EMMCA untuk Cloud / IPSO-GWO untuk Hybrid

Skenario 1 (Pusat Data Cloud): EMMCA sangat ideal karena Modified Min-Min segera memprioritaskan potongan genom terpendek, lalu Cuckoo Search meratakan beban ke seluruh node VM server secara adil (efisiensi speedup meningkat s.d. 15.8%).

Skenario 2 (Lab Bergerak / Lapangan): IPSO-GWO lebih unggul jika sequencer DNA portabel (seperti Oxford Nanopore) memproses data di lab lapangan dengan suplai daya genset/baterai terbatas (hemat energi s.d. 76%).

Batasan & Asumsi: Regulasi privasi medis (HIPAA/UU PDP) menuntut data pasien dienkripsi sebelum ditransfer, menimbulkan overhead waktu komputasi tambahan.

LIGO & Montage: Memproses data koalesensi lubang hitam biner dan menyatukan ribuan citra teleskop inframerah NASA berformat FITS menjadi mosaik langit mosaik raksasa.

16 · Panduan Arsitek Sistem

Kapan Memilih IPSO-GWO & Kapan Memilih EMMCA?

Pilih IPSO-GWO Jika:
  • Arsitektur mencakup perangkat Edge/IoT, gateway Fog, dan server Cloud.
  • Konsumsi energi & efisiensi listrik adalah Key Performance Indicator (KPI) utama sistem Anda (Green Computing).
  • Skala workflow sangat masif (ratusan hingga ribuan task berantai).
  • Anda memerlukan algoritma dengan struktur data ringan yang mudah diintegrasikan ke orkestrator kontainer.
Pilih EMMCA Jika:
  • Arsitektur beroperasi murni di lingkungan Cloud Datacenter / Private Cloud.
  • Keseimbangan beban (Load Balancing) antar VM adalah prioritas tertinggi untuk mencegah server bottleneck atau SLA breach.
  • Skala alur kerja berada pada level kecil hingga menengah (≤ 100–200 task).
  • Anda ingin jadwal awal yang terjamin valid dan terstruktur langsung melalui heuristik Modified Min-Min tanpa memulai dari solusi acak.

Kesimpulan Akhir: Kedua algoritma mewakili paradigma mutakhir dalam orkestrasi alur kerja awan modern. Masa depan riset mengarah pada penggabungan metrik Green Computing IPSO-GWO dengan keunggulan Load Balancing EMMCA.
